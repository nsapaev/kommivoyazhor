# Маршруты

Простой и дешёвый планировщик маршрутов для небольшого бизнеса с 1–5 машинами.
Указали склад и адреса, выбрали число машин — получили для каждого водителя ссылку
с готовым маршрутом в Яндекс Картах.

## Как устроено

| Часть | Что делает |
|---|---|
| `frontend/` | React + TypeScript + Leaflet: склад, адреса, карта («Схема» / «Гибрид»), карточки маршрутов |
| `backend/app/osrm.py` | время и расстояние между точками по реальным дорогам (OSRM) |
| `backend/app/solver.py` | OR-Tools: распределяет точки по машинам и выбирает порядок |
| `backend/app/links.py` | ссылка `yandex.ru/maps/?rtext=…` — бесплатно, без ключа |
| `backend/app/geocode.py` | поиск адреса через Nominatim (OpenStreetMap) |
| `backend/app/auth.py` | регистрация компании, вход, выход; сессии в httpOnly-cookie |
| `backend/app/plans.py` | склад и настройки компании, маршрутные листы: черновик → построен, история, «Повторить» |
| `backend/app/routing.py` | расчёт: матрица OSRM → OR-Tools → ссылки и линии маршрутов |
| `backend/app/db.py` | SQLite: компании, пользователи, сессии, настройки, маршрутные листы |

Нагрузка на машины выравнивается: самый длинный маршрут получает штраф, поэтому одна машина не возит всё.
Если OSRM недоступен, расчёт идёт по прямой, а на экране появляется предупреждение, что время и километры примерные.

## Запуск для разработки

```bash
# бэкенд (Python 3.12: brew install python@3.12)
python3.12 -m venv .venv && .venv/bin/pip install -r backend/requirements.txt
cd backend && ../.venv/bin/uvicorn app.main:app --reload --port 8000

# фронтенд, в другом терминале
cd frontend && npm install && npm run dev      # http://localhost:5173
# проверка типов: npm run typecheck
```

В режиме разработки используется публичный демо-сервер OSRM (`router.project-osrm.org`).
Он подходит только для проверки: там есть лимиты, и для работы с клиентами он не предназначен.

Тесты: `cd backend && ../.venv/bin/python -m pytest -q`

## Вход

Без входа работает только экран входа и регистрации, весь API закрыт.
Регистрация создаёт компанию и её владельца. Пароли хранятся как scrypt-хеш, сессия живёт 30 дней.
После 10 неверных паролей подряд вход для этого email блокируется на 15 минут.

## Маршрутные листы

Каждый день — свой маршрутный лист: точки, число машин, минуты на точку и построенный результат.
Всё хранится на сервере, поэтому одинаково видно с телефона и компьютера.

- Склад один на компанию и задаётся один раз в настройках.
- Любая правка точек или настроек сбрасывает построенный маршрут, и его нужно построить заново.
- В результате сохраняется снимок склада, поэтому история не меняется, если склад потом сменят.
- «Повторить» создаёт новый лист на сегодня с теми же точками и настройками.
- Последние выбранные число машин и минуты на точку становятся значениями по умолчанию для новых листов.

## Точки: время, телефон, импорт

- У каждой точки можно указать телефон, комментарий для водителя и окно доставки («с 10:00 до 12:00»).
  Окна учитывает оптимизатор: раньше окна машина ждёт, опоздание сильно штрафуется. В карточке машины —
  время прибытия на каждую точку, опоздания подсвечены красным. Время считается от «Начала смены».
- Список точек можно вставить из Excel (столбцы с заголовками) или загрузить файлом `.xlsx` / `.csv`.
  Колонки узнаются по заголовкам: «Адрес», «Клиент», «Телефон», «С», «До» или «Окно», «Комментарий»,
  «Широта»/«Долгота». Образец: `/api/import/template.csv`.

## Страница водителя

После построения у каждой машины есть секретная ссылка `/d/<token>` — без входа и регистрации.
Водитель видит точки по порядку, звонит клиенту, открывает навигатор (от своего местоположения)
и отмечает «Доставлено» / «Не получилось». Диспетчер видит отметки в карточке машины (обновляются раз в 30 с).
Ссылка не меняется при пересчёте, отметки привязаны к точке (координатам) и переживают пересчёт.

## Запуск на сервере (свой OSRM)

```bash
./scripts/prepare_osrm.sh                               # один раз: карта Узбекистана
docker compose up -d --build                            # http://сервер:8000
```

Для Узбекистана хватит самого простого VPS: 2 ГБ памяти на работу, 4 ГБ на подготовку карты.

## Настройки (переменные окружения)

- `DB_PATH` — файл базы, по умолчанию `backend/data/app.db`
- `COOKIE_SECURE=1` — обязательно включить, когда сайт работает по HTTPS
- `OSRM_URL` — адрес OSRM (в docker-compose уже указан)
- `MAX_STOPS` — максимум точек в одном расчёте, по умолчанию 100
- `GEOCODE_COUNTRY` — в какой стране искать адреса, по умолчанию `uz`
- `GEOCODE_VIEWBOX` — границы города для поиска «запад,север,восток,юг», по умолчанию Ташкент; пусто — вся страна
- `NOMINATIM_URL` — свой Nominatim, если публичного станет мало (лимит 1 запрос/сек)

## Ограничения MVP

- Нет учёта вместимости машин и временных окон клиентов («с 10 до 12»): solver это умеет, добавим, когда понадобится.
- Публичный Nominatim медленный на больших списках адресов (1 адрес в секунду).
- Один пользователь на компанию (владелец). Приглашение сотрудников и восстановление пароля — следующим шагом.
- «Гибрид» использует бесплатные спутниковые снимки Esri. Для коммерческого запуска по их условиям нужен бесплатный аккаунт ArcGIS (или можно перейти на другой источник снимков).
